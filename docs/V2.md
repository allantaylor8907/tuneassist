# tuneassist v2 — assessment & GUI design

## The refactor assessment (June 2026)

Question asked: does the codebase need a refactor to meet the stated goals —
local-first Windows app, beautiful and compelling visuals, information that's
accurate *and* digestible from total beginner to professional tuner?

**Answer: the engine does not; the presentation layer does.**

- The analysis engine (~4,000 lines: `diagnostics`, `engine_gm`, `holley`,
  `stages`, `triage`, `spark`, `cams`, `profile`, `core`) is tested, validated
  against real logs from six+ hardware configs, and fully decoupled behind
  `core.analyze_log(...).to_dict()`. Nothing about the goals requires changing
  it. It is the product's moat — leave it alone.
- The Textual TUI is well-built but capped: a terminal cannot render smooth
  gradients, real charts, animation, or mouse-first progressive disclosure.
  "Beautifully compelling" and "beginner-friendly" both point past it.

So v2 is **additive**: a new GUI face over the same headless core. No engine
rewrite, no data-model break, the JSON contract only gains keys.

## v2 architecture (decided)

- **Local web GUI.** A stdlib `http.server` bound to `127.0.0.1` on a random
  port with a random URL token, serving static assets + a JSON API that is a
  thin wrapper over `core` / `garage` / `update` / `submit`.
- **Window = Edge app mode.** Windows 10/11 always ship Edge; `msedge
  --app=http://...` gives a chromeless native-feeling window with **zero new
  Python dependencies** (no pywebview/pythonnet/Qt), keeping the PyInstaller
  one-file build and self-updater untouched. Fallback: default browser.
- **Lifecycle:** the frontend heartbeats `/api/ping`; the server exits ~10s
  after the window closes. `--gui-dev` serves for a normal browser (iterate
  with devtools).
- **Charts: Apache ECharts**, vendored as a single static file (offline,
  no node toolchain). Native heatmap / gauge / line+zoom — exactly the visual
  vocabulary tuning data needs.
- **No build step.** Hand-written HTML/CSS/JS, vendored chart lib. Matches the
  project's no-heavy-deps convention and keeps contributions approachable.

## Design system (from the stated preferences)

- **Light AND dark themes**, one click, persisted. CSS custom properties;
  Segoe UI Variable (the Win11 system face) for a native-modern feel.
- **Modern SaaS cleanliness**: card layout, generous spacing, restrained color;
  severity colors reserved for meaning (critical red / warning amber /
  opportunity green / info gray) so alarm = information, not decoration.
- **Guided journey always available**: the 8-stage journey stepper is permanent
  chrome; a "verdict hero" states the single next move in plain English. A
  Beginner/Expert toggle controls progressive disclosure — beginners see the
  one thing to do; experts expand into dense grids.
- **Data-forward with explanations**: every chart carries a "What am I looking
  at?" expander and hover tooltips that translate cells into plain English
  ("PCM added 7% fuel here over 44 samples — raise VE in this cell").
- **Point-in-time fault identification**: a scrubbing timeline (RPM / AFR /
  trims / knock traces with zoom + event markers) so a user can see *when* the
  bad behavior happened, not just that it happened. Gauge-style readouts ride
  the hover cursor.

## Rollout (parallel → cutover)

1. v0.1.x (TUI) keeps shipping from `main`, untouched.
2. v2 GUI grows on the `gui-v2` branch behind `--gui` until it reaches parity:
   garage CRUD, setup, analyze/report, TSV copy, share-log, update flow.
3. At cutover: GUI becomes the no-args default; `tui.py`, `panels.py`,
   `demo.py` move to `legacy/` (kept importable for one release, then frozen)
   per the project's retain-history requirement. `--batch`/`--json` are
   unaffected forever.

## API surface (v2.0)

| Endpoint | Maps to |
|---|---|
| `POST /api/analyze` `{path, opts}` | `core.analyze_log().to_dict()` (+ timeseries/tsv) |
| `POST /api/analyze-upload` (file bytes) | same, via temp file (drag & drop) |
| `GET/POST /api/garage…` | `garage` load/upsert/rename/delete |
| `GET /api/presets` | engine presets, mods, cam tiers, architectures, fuels |
| `POST /api/pick-file` | native file dialog (PowerShell, reused from TUI) |
| `GET /api/version` · `POST /api/update` | `update` check / self-update |
| `POST /api/submit` | `submit` bundle + reveal |
| `POST /api/ping` | heartbeat lifecycle |

Contract additions to `to_dict()` (all additive): `timeseries` (downsampled
traces + knock events), per-cell `n` and cross-check labels in `correction`,
`maf` axis/n, `spark.change/action` grids, `tsv.{correction,maf,spark}`.
